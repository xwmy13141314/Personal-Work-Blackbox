## 三、合并方案（建议）

### 基线选择：以 **GitHub v5.3.0** 为基线

理由：它是官方主线，且是唯一包含 v5.x 输入采集架构（UIA / COM + 拼音 2.0）的版本；本地的 v4.5.0 只是 v4.3.1 之上的单点改动（21 文件），**以小改大**成本最低、风险最小。

### 合并规则

1. 以 GitHub v5.3.0 全量代码为底
2. 把本地独有能力（B1–B6）**按 v5.3 的代码风格重新实现 / 移植**上去，而不是把 v4.5.0 的文件直接覆盖
3. 冲突文件（A1–A16）一律以 GitHub 版为底，只把本地"能力"追加进去
4. 明确弃用：键盘钩子死代码清理（A5）、本地旧版前端文件（A11–A16）、本地 `insights` 表（改用 `notes`）
5. 版本号统一 **v5.4.0**，CHANGELOG / PRD / README / 使用说明 / About 页一起对齐

### v5.4.0 合并后的功能全集

| 来源 | 功能 |
|---|---|
| GitHub v5.0–v5.3 | 个人工作台（驾驶舱 + 速记 + AI 周度洞察 + 全局搜索） |
| GitHub v5.2–v5.3 | 输入采集准确性（UIA / COM 真实上屏文本 + 拼音智能识别 2.0） |
| **本地新增** | 速记**双写「每日洞察」收件箱**（喂给 AI 蒸馏流程） |
| **本地新增** | 速记**标签体系**（标签云 + 标签筛选） |
| **本地新增** | **Ctrl+Alt+I** 全局速记呼出 |
| **本地新增** | 待办删除**文件双归档**（按月 Markdown + JSONL，可找回） |
| **本地新增** | 洞察页**收件箱配置与连接状态** |
