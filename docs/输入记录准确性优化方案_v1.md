### 实现期踩坑记录（重要，避免重复）

1. **WinUI3 焦点与编辑控件是兄弟分支**
   ```
   WindowControl class=Notepad
     PaneControl class=NotepadTextBox
       DocumentControl class=RichEditD2DPT      ← 编辑控件
     PaneControl class=DesktopWindowContentBridge
       PaneControl class=Windows.UI.Input.InputSite.WindowClass  ← 焦点在这
   ```
   焦点元素的父链通往**桌面/任务栏**（不是本窗口），所以"向下搜"和"沿父链找窗口"都不通。
   → 必须用 `GetForegroundWindow()` 取前台窗口句柄 → `ControlFromHandle` → 子树搜索。

2. **`GetForegroundWindow()` 必须设 `restype = c_void_p`**，否则 64 位下句柄截断。

3. **Win11 记事本会自动恢复上次内容** —— 测试时必须先清空，否则初始基线就带着旧文本（本次调试为此绕了一圈）。

4. **`uiautomation` 2.0.29 的 Pattern 读取**：
   ```python
   p = ctrl.GetPattern(auto.PatternId.ValuePattern)   # ✅
   p.Value
   # ❌ ctrl.IsValuePatternAvailable() / ctrl.GetValuePattern() 均不存在
   ```

## 1. 实测结论(v2.0 核心)

### 1.1 三路采集能力矩阵(实测)

| 应用类型 | 代表应用 | 采集手段 | 读取方式 | 实测结果 |
|---|---|---|---|---|
| **Win32 标准控件** | 记事本、WinForms/Qt 程序 | UIA `DocumentControl` / `EditControl` | `ValuePattern` / `TextPattern` / `LegacyIAccessible` | ✅ **三路均读到完整中文** |
| **Chromium 系** | WorkBuddy、飞书、Chrome、Edge、VS Code | UIA `EditControl` | 同上三路 | ✅ **逐字增长零丢失** |
| **Office 系** | WPS 表格 / WPS 文字 / MS Office | WPS COM(`Ket`/`Kwps`)/ Office COM | `ActiveCell.Value2` / `Selection.Text` | ✅ **精确读到单元格内容** |
| **自绘/游戏类** | DirectX 界面 | —— | —— | ❌ 无 API 可读 → 走拼音兜底 |

### 1.2 实测证据

**证据 A — 记事本(标准控件,三路全通)**
```
Notepad.exe lv0 DocumentControl [V] '天线问题今天必须搞定 GR1003' ★汉字
Notepad.exe lv0 DocumentControl [T] '天线问题今天必须搞定 GR1003' ★汉字
Notepad.exe lv0 DocumentControl [A] '天线问题今天必须搞定 GR1003' ★汉字
```

**证据 B — WorkBuddy / Chromium(逐字追踪,零丢失)**
用户在聊天框输入"上面两句是我打的内容",被逐字完整记录:
```
15:02:57.636  EditControl [V] '上面'
15:02:58.508  EditControl [V] '上面两句'
15:02:59.398  EditControl [V] '上面两句是我'
15:03:00.250  EditControl [V] '上面两句是我打的'
15:03:01.115  EditControl [V] '上面两句是我打的内容'
```
→ **标点准确、汉字完整、无拼音残留**。这是目标效果。

**证据 C — WPS 表格(COM 接口精确读取)**
```
[成功] GetActiveObject("Ket.Application")
ActiveCell.Address : $B$66
ActiveCell.Value2  : '务必把这两个项目给确认下来'    ← 用户在单元格里输入的内容
ActiveWorkbook     : 每日工作事项跟踪表.xlsx
ActiveSheet        : GR1003
```

**证据 D — WPS 表格 UIA 无效(反证,故必须走 COM)**
```
wps.exe lv4 WindowControl [N] '每日工作事项跟踪表.xlsx *'
wps.exe lv7 WindowControl [N] '每日工作事项跟踪表.xlsx * - WPS 表格'
```
→ 焦点在单元格时,UIA 树只暴露窗口标题,**无单元格文本节点**。WPS 表格必须走 COM。

### 1.3 三个关键工程结论

**① 焦点元素类型是"能不能读"的判据**
`GetFocusedControl()` 的返回值分两类:
- `EditControl` / `DocumentControl` → **是编辑目标,可直接读**(值即输入内容)
- `GroupControl` / `PaneControl` → **是容器,必须拒绝**(实测其 `Name` 装着整个页面的文本,661 字符,直接入库就废了)

**② 拿到的是"全量文本",必须做差分**
UIA 给的是输入框的**完整内容**(如整个单元格、整篇文档),不是"这次打的那几个字"。
→ 必须与上一次的值对比,**提取增量**再入库。从证据 B 看,增量追加是主模式,前缀差分有效。

**③ 采集是被动的,不依赖按键事件**
UIA/COM 是"查询式"读取,不需要等空格触发、不需要 35ms 延时、不受 TSF-only 输入法影响。
→ 这从根本上**绕开了现有架构的全部 P0 缺陷**。

## 3. 方案设计

### 3.1 采集层:三路融合 + 择优

```
                    ┌─────────────────────────────────┐
   焦点变化/定时 tick │  采集调度器(新,~0.3s)          │
                    └────────────┬────────────────────┘
                                 ↓
              ┌──────────────────┴──────────────────┐
              ↓                                     ↓
   【路径 1】UIA 焦点直读                    【路径 2】WPS/Office COM
   GetFocusedControl()                       GetActiveObject("Ket.Application")
   ├ EditControl/DocumentControl?            ├ ActiveCell.Value2
   ├ 读 V → ValuePattern.Value                └ Selection.Text
   ├ 读 T → TextPattern.DocumentRange
   └ 读 A → LegacyIAccessiblePattern        命中条件:前台进程 ∈ {et,wps,wpp,EXCEL,WINWORD}
   拒绝 GroupControl/PaneControl
              ↓                                     ↓
              └──────────────────┬──────────────────┘
                                 ↓
                      【差分引擎】与上次值对比,提取增量
                                 ↓
                      ┌──────────┴──────────┐
                      ↓                     ↓
                 有增量 → 直接入库      无数据 → 【路径 3】拼音引擎兜底
                 (汉字,无需转换)       (现有 keyboard_hook 键流 + v1.1 引擎)
```

**优先级仲裁规则:**
1. COM 可用(命中 WPS/Office 进程)→ **以 COM 为准**(最精准,单元格级)
2. 否则 UIA 拿到编辑控件文本 → **以 UIA 为准**
3. 两者都无数据 → **键盘键流 + 拼音引擎兜底**
4. 同一时刻只有一路生效,避免多源冲突(替代现有粗糙的"汉字数比大小")

### 3.2 差分算法(关键)

```python
def diff_increment(old: str, new: str) -> str:
    """从全量文本变化中提取用户本次新增的输入"""
    if new == old:
        return ""                          # 无变化
    if new.startswith(old):
        return new[len(old):]              # 尾部追加(主模式,见实测证据 B)
    if old.startswith(new):
        return ""                          # 退格删除,不产出
    # 中间修改/粘贴替换:取最长公共前缀之后的部分
    lcp = 0
    for a, b in zip(old, new):
        if a != b: break
        lcp += 1
    return new[lcp:]
```

**配套状态管理:**
- 每个 `(hwnd/进程, 控件标识)` 维护独立的 `last_value`,避免跨窗口污染(替代 P1-5)
- 窗口/控件切换时重置基线,首帧不入库(避免把已有内容当成"新输入")
- 长度变化超阈值(如 >500 字符)判为粘贴/整体替换,标记 `is_paste`

### 3.3 拼音引擎兜底(已实现,待重打包生效)

已在 2026-09-10 完成并测试通过(22/22 用例):
- **前缀匹配**:`jint→今天` / `wanc→完成` / `xiangm→项目`(60+ 条映射)
- **同池贪心分词**:避免完整音节吃掉前缀
- **短序列优先 fallback**:避免 DAG 选错路径(`yao wan` 不再变"药丸")
- **编号保护**:`GR1003` 永不转换
- 实测样本 1:`nihao,jintyaowancgr1003xiangmdewaiguanjianmopinggu` → `你好,今天要完成gr1003项目的外观建模评估` ✅

**已知上限(诚实说明):** raw 拼音有不可逆丢字母(`tupian→tup`),这部分**任何算法都无法还原**,只能靠采集层修好。

### 3.4 AI 增强按钮修复

**问题:** 打包 JS 的禁用条件 `disabled = ... || !(detail?.segments.length)`,在日期明细视图下 `detail` 未加载 → 按钮恒灰。

**修复:**
- 未展开会话时,`detail` 自动取当前可见的第一条;或按钮改为"展开后可点"的提示态
- 同时:前端 `texts` 改为"仅传未过滤且含拼音的片段",减少无效 LLM 调用
- "AI 调用异常" 补充具体原因(超时/Key 无效/额度),不再统一文案

## 7. 风险与回退

| 风险 | 影响 | 概率 | 应对 |
|---|---|---|---|
| UIA 在部分应用不暴露编辑控件(如未开无障碍的 Chromium) | 该应用退化 | 中 | 自动降级到拼音兜底;不报错、不阻塞 |
| WPS COM 需专业版/旗舰版,家庭版不开放 | 仅 WPS 场景失效 | 中 | 本机已实测可用;不可用时自动跳过 |
| COM 调用阻塞采集线程 | 卡顿 | 低 | 独立线程 + 超时(1s)+ 失败退避 |
| 差分歧义(中间修改/粘贴) | 增量不准 | 中 | 超阈值标记 `is_paste`,不做字符级猜测 |
| 多源重复入库 | 数据重复 | 中 | 仲裁规则保证单路生效 + 时间窗去重 |
| 全部改动集中在采集层 | 影响面大 | 中 | **全部带 `accurate_mode` 开关**,一键回退 |

**回退方案:** 配置 `collection.accurate_mode: false`,采集层立即回到 v5.2.0 的键盘钩子链路,无需改代码、无需重装。

## 8. 附录:验证方法(可复现)

本轮验证使用的两个脚本,保留在 `scripts/` 供复现:

| 脚本 | 用途 |
|---|---|
| `scripts/diag_uia_edit.py` | UIA 编辑目标定位诊断:焦点元素 + 祖先链,4 种读法(V/T/A/N),输出"应用\|控件\|读法\|文本" |

**COM 验证命令:**
```python
import win32com.client, pythoncom
pythoncom.CoInitialize()
app = win32com.client.GetActiveObject("Ket.Application")   # WPS 表格
print(app.ActiveCell.Value2)                                # 当前单元格内容
```

**注意(踩坑记录):**
- `uiautomation` 2.0.29 的 API 是 `GetPattern(PatternId)`;
  常见的 `IsValuePatternAvailable()` / `GetValuePattern()` / `SetValue()` **不存在**
- `SetWindowsHookExW` 必须设 `restype = c_void_p`,否则 64 位下句柄截断、钩子静默失效
- 项目环境须用 **system Python**(有 pywin32);managed Python 缺 `pywin32`/`win32clipboard`
